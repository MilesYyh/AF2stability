# 5.train_ddg_mlp.py

## 脚本定位

这是当前 AF2stab 主流程最后一个脚本，用于把 `4.extract_single_repr_features.py` 产出的 1152 维特征输入到一个 MLP 中，完成 ddG 训练与评估。

它既能做最简单的训练集拟合，也能做 holdout 和 K-fold CV 评估。

---

## 这个脚本做什么

给定一个包含：

- `X`：形状 `(N, 1152)` 的特征矩阵
- `y`：形状 `(N,)` 的 ddG 标签
- `sample_ids`

的 NPZ 文件，这个脚本会：

1. 构建 MLP
2. 训练模型
3. 计算回归指标
4. 写出模型参数与 summary JSON

---

## 模型结构

`DdGMlp` 定义的网络是：

- `1152 -> 1152`
- `ReLU`
- `1152 -> 512`
- `ReLU`
- `512 -> 512`
- `ReLU`
- `512 -> 1`

这和你当前按照论文实现的基础 MLP 结构一致。

---

## 代码是怎么组织的

### 1. 顶部常量与模型类

- `VERSION`
- `DdGMlp`

模型定义单独放在前面，便于以后替换成更复杂网络。

### 2. 指标与训练 helper

- `compute_regression_metrics()`
  - 计算 `mae / mse / rmse / pearson`
- `require_metric()`
  - 确保特定指标不为 `None`
- `train_epoch()`
  - 执行一个 epoch 的训练
- `predict()`
  - 在给定数据上做前向推理并计算评估 loss
- `build_loader()`
  - 统一构建 DataLoader

### 3. 划分 helper

- `shuffled_indices()`
- `split_train_val_indices()`
  - holdout 模式使用
- `build_kfold_indices()`
  - CV 模式使用

### 4. IO helper

- `resolve_repo_path()`
- `load_feature_dataset()`
- `write_summary()`

### 5. `main()`

`main()` 是总编排器：

1. 读取 NPZ
2. 校验 `X` / `y` 形状
3. 建模与设备选择
4. 根据运行模式进入不同分支
5. 保存 state dict
6. 写 summary

---

## 支持哪些运行模式

参数：

- `--mode train_only`
- `--mode holdout`
- `--mode cv`

### 1. `train_only`

只在整份输入数据上训练，不做外部分割评估。

适合：

- 验证训练链路能跑
- 观察训练 loss 是否下降

不适合：

- 对外汇报泛化性能

### 2. `holdout`

做单次随机 train/val 切分。

相关参数：

- `--val-fraction`
- `--seed`

适合：

- 快速得到一次验证集性能

### 3. `cv`

做 K-fold 交叉验证。

相关参数：

- `--num-folds`
- `--seed`

适合：

- 给当前阶段提供更稳定的基线结果

---

## 小样本时怎么处理

如果样本数 `< 2`，脚本不会假装训练，而是进入：

- `smoketest_minimal_train_step`

这个模式只验证：

- 前向传播
- loss 计算
- 反向传播
- 参数更新

这保证了在极小样本时，summary 的含义仍然清楚。

---

## 指标是怎么计算的

脚本会输出：

- `MAE`
- `MSE`
- `RMSE`
- `Pearson`

其中 Pearson 只有在以下条件满足时才会给值：

- 样本数至少为 2
- `y_true` 标准差不为 0
- `y_pred` 标准差不为 0

否则返回 `None`。

---

## 为什么 summary 现在默认不写 sample ID 明细

之前 summary 会把几千条 `sample_ids` 全部写进去，导致：

- JSON 很大
- 不利于比较不同实验
- 真正关心的指标被淹没

现在默认行为改成：

- **只写统计和指标**

如果确实需要明细，再显式加：

- `--include-sample-ids`

## 如何运行

### 1. 只训练不评估

```bash
python scripts/5.train_ddg_mlp.py \
  --input-npz data/processed/single_repr_features_full_partial.npz \
  --mode train_only \
  --summary-json results/models/ddg_mlp_full_partial_train_only_summary.json \
  --state-dict results/models/ddg_mlp_full_partial_train_only_state_dict.pt
```

### 2. Holdout 评估

```bash
python scripts/5.train_ddg_mlp.py \
  --input-npz data/processed/single_repr_features_full_partial.npz \
  --mode holdout \
  --val-fraction 0.2 \
  --seed 42 \
  --summary-json results/models/ddg_mlp_full_partial_holdout_summary.json \
  --state-dict results/models/ddg_mlp_full_partial_holdout_state_dict.pt
```

### 3. 10-fold CV

```bash
python scripts/5.train_ddg_mlp.py \
  --input-npz data/processed/single_repr_features_full_partial.npz \
  --mode cv \
  --num-folds 10 \
  --seed 42 \
  --summary-json results/models/ddg_mlp_full_partial_cv10_summary.json \
  --state-dict results/models/ddg_mlp_full_partial_cv10_state_dict.pt
```

### 4. 如果要把 sample IDs 也写进 summary

```bash
python scripts/5.train_ddg_mlp.py \
  --input-npz data/processed/single_repr_features_full_partial.npz \
  --mode holdout \
  --include-sample-ids
```

## 输出有哪些

### `state_dict`

保存 PyTorch 模型参数，可以后续复现推理或继续训练。

### `summary_json`

保存：

- 样本数
- 特征维度
- 训练参数
- 模式
- 各类 loss
- 各类回归指标
- 若是 CV，还会保存每个 fold 的结果与聚合统计

---

## 运行后怎么读结果

### `train_only`

重点看：

- `final_loss`
- `min_loss`

这只说明模型能否拟合训练集。

### `holdout`

重点看：

- `train_metrics`
- `val_metrics`

如果训练很好、验证明显差，说明过拟合很强。

### `cv`

重点看：

- `aggregate_metrics`
- `folds`

这是当前最适合对外比较的结果层级。

---

## 常见坑

### 1. 默认输入路径还是早期 smoketest 风格

正式主流程中建议总是显式传入 `--input-npz`。

### 2. `train_only` 不是泛化性能

它只能看拟合效果，不能拿来直接和论文对比。

### 3. 当前 CV 是随机切分

虽然能作为工程 baseline，但不是论文的 residue-based / homology-aware 口径。

### 4. `state_dict` 在 CV 模式下不是每个 fold 单独存一份

当前脚本会写一个 state dict 路径，但主要价值在 summary 指标，不在单个模型权重归档。
