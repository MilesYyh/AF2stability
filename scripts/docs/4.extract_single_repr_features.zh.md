# 4.extract_single_repr_features.py

## 脚本定位

这个脚本负责把 AlphaFold 输出的 WT / mutant `single representation` 转换成论文训练所需的 **1152 维位点特征**。

它是真正把“结构预测产物”转成“可训练机器学习特征”的脚本。

---

## 它解决什么问题

AlphaFold 的输出目录里虽然有 `single_repr_model_*.npy`，但训练阶段真正需要的是：

- WT 在突变位点的 384 维向量
- mutant 在突变位点的 384 维向量
- 二者差向量 384 维

然后把这三段拼接成：

- `384 + 384 + 384 = 1152`

这个脚本就实现了这个“位点抽取 + 向量拼接”的过程。

---

## 输入与输出

### 输入

- manifest：告诉脚本样本位点、protein_id、sample_id、ddG 等信息
- representation 输出目录：里面按 `protein_id` 和 `sample_id` 存放 WT / mutant 的 `.npy`

当前脚本默认值仍然保留了较早的 smoketest 风格路径，因此在正式主流程里建议**显式传参**。

### 输出

- `output_csv`
  - 每条已成功抽取样本的一行元数据
- `output_npz`
  - 真正供训练脚本消费的 `X / y / sample_ids`
- `summary_json`
  - 记录抽取多少条、缺多少条、缺失原因示例等

---

## 代码是怎么写的

### 1. 顶部常量

- `VERSION`
- `OUTPUT_FIELDNAMES`

`OUTPUT_FIELDNAMES` 的作用是固定输出 CSV 的结构，避免空结果或 partial 结果导致表头不稳定。

### 2. helper

- `resolve_repo_path()`
  - 把输入输出路径统一解释为仓库根目录下的路径
- `load_manifest_rows()`
  - 读取 manifest
- `write_summary()`
  - 写 summary JSON

### 3. `main()`

`main()` 里做的核心事情有：

1. 读取 manifest
2. 对每一行样本定位 WT / mutant `.npy`
3. 如果文件缺失，做缺失统计
4. 如果文件存在，按位点取向量
5. 拼接成 1152 维特征
6. 写 CSV / NPZ / summary

## 特征是怎么计算的

### 第一步：确定 WT / mutant 表示文件路径

- WT 路径：`repr_output_dir / protein_id / single_repr_<model>.npy`
- mutant 路径：`repr_output_dir / sample_id / single_repr_<model>.npy`

### 第二步：取突变位点索引

manifest 里的 `position` 是 **1-based**，代码会先转成：

```python
residue_index = position - 1
```

### 第三步：抽取向量

- `wt_vec = wt_repr[residue_index]`
- `mut_vec = mut_repr[residue_index]`
- `diff_vec = mut_vec - wt_vec`

### 第四步：拼接

```python
feature_vec = np.concatenate([wt_vec, mut_vec, diff_vec], axis=0)
```

最终要求：

- `feature_vec.shape == (1152,)`

如果 shape 不对，脚本会直接报错，不会悄悄吞掉。

## 为什么这个脚本支持 partial / incremental extraction

full-run 可能会持续跑很久，不一定等全部任务结束后才开始下游处理。

所以脚本增加了这样的行为：

- 如果 WT 或 mutant 表示文件缺失，默认**跳过并记录统计**
- 不会因为少量未完成任务而中断整批抽取

这样你可以在结构预测还在继续时，周期性地把已经完成的样本先变成训练特征。

---

## strict 模式有什么用

参数：

- `--strict-missing`

默认情况下：

- 缺文件 → 记到 summary → 跳过

开启 strict 后：

- 缺文件 → 直接抛 `FileNotFoundError`

这很适合两种场景：

1. 你已经认为 full-run 应该完整结束，想强制检查是不是还缺样本
2. 你在做最终正式特征产物时，不想混入 partial 行为

---

## summary.json 记录了什么

比较关键的字段有：

- `manifest_rows`
- `rows_extracted`
- `rows_missing_any`
- `rows_missing_wt_only`
- `rows_missing_mut_only`
- `rows_missing_both`
- `missing_examples`
- `feature_matrix_shape`
- `label_shape`

这让你可以区分：

- 是 WT 没好
- 是 mutant 没好
- 还是两边都没好

## 如何运行

### 正式 full-run partial 特征抽取（推荐）

```bash
python scripts/4.extract_single_repr_features.py \
  --input-manifest data/manifests/fireprotdb_phase1_af2_manifest.csv \
  --repr-output-dir results/af2/single-repr-full/outputs \
  --output-csv data/processed/single_repr_features_full_partial.csv \
  --output-npz data/processed/single_repr_features_full_partial.npz \
  --summary-json data/processed/single_repr_features_full_partial_summary.json
```

### 最终严格检查版

```bash
python scripts/4.extract_single_repr_features.py \
  --input-manifest data/manifests/fireprotdb_phase1_af2_manifest.csv \
  --repr-output-dir results/af2/single-repr-full/outputs \
  --output-csv data/processed/single_repr_features_full.csv \
  --output-npz data/processed/single_repr_features_full.npz \
  --summary-json data/processed/single_repr_features_full_summary.json \
  --strict-missing
```

## 运行后应该检查什么

重点看：

1. `rows_extracted`
2. `rows_missing_any`
3. `rows_missing_mut_only`
4. `feature_matrix_shape`

如果 `rows_missing_mut_only` 很高，通常说明 WT 已经跑出来了，但大量 mutant 还没完成。

## 常见坑

### 1. 默认参数偏旧

当前默认参数仍然偏向早期 smoketest 路径，所以正式使用时建议显式传 `--input-manifest` 和 `--repr-output-dir`。

### 2. 位点索引必须从 1-based 转 0-based

这里是整个特征流程里最容易犯错的地方之一。

### 3. `.npy` 的存在不代表所有模型都导出了

当前脚本只按一个 `model_name` 去找文件。

### 4. 这是位点级特征，不是全序列特征

脚本只抽取一个残基位点的表示，不会保留整个 `(N_res, 384)` 矩阵做训练。
